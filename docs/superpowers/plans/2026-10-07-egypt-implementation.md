# Egypt Museum Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Реализовать русскоязычный музейный сайт с согласованным порталом, пролётом WebGL и семью информационными главами.

**Architecture:** Один статический повествовательный документ, собранный Vite. Three.js управляет пространственной сценой; единая модель прогресса связывает камеру, свет, фокус и HTML-содержимое. Документ остаётся доступен без WebGL и JavaScript.

**Tech Stack:** Vite, модульный JavaScript, Three.js/WebGL, GLSL, GSAP ScrollTrigger, Lenis; встроенный Node test runner для модели пролёта; браузерная проверка для пользовательских сценариев.

**Spec:** [Согласованное проектное описание](../specs/2026-10-07-egypt-design.md).

## Global Constraints

- «Основной акцент — компьютеры. Телефоны получают адаптивную читаемую версию с уменьшенной сложностью эффектов.»
- «Первая поставка — работающий локальный проект в текущей папке и сборка для размещения на статическом хостинге.»
- «Публикация и домен требуют отдельного выбора пользователя.»
- «Первый экран повторяет макет A» — `.impeccable/mocks/egypt-a.png`, 1672×941.
- «Текст и кнопки создаются средствами HTML/CSS, а не встраиваются в картинку.»
- «Семь глав: Нил, Пирамиды, Фараоны, Письменность, Боги, Повседневная жизнь, Наследие.»
- «Стек: Vite + модульный JavaScript + Three.js/WebGL + GLSL + GSAP ScrollTrigger + Lenis.»
- «Цель — плавные 60 FPS на доступном современном компьютере; это проверяемая цель, а не гарантия для всех устройств.»
- «Исходные prompt, ref и невыбранные макеты сохраняются.»

## Review Focus

1. Выключенный JavaScript или недоступный WebGL: все семь глав и источники доступны; первый экран сохраняет статическую композицию.
2. Быстрая прокрутка и немедленный возврат: камера и свет определяются текущим прогрессом, без накопления старых анимаций.
3. Включённое уменьшение движения: нет длинного закрепления, наклона, засветки и непрерывного песка.
4. Узкий экран и изменение размера: текст читаем, документ не имеет горизонтального переполнения, источник изображения не растягивается неправильно.
5. Сбой изображения, потеря WebGL-контекста или скрытая вкладка: текст остаётся доступен, лишний рендер прекращается, переключение на статический режим не ломает прокрутку.

## File Structure

- `index.html` — весь семантический документ, семь глав, ссылки, метаданные и favicon.
- `src/styles.css` — типографика, измеренная композиция, карточки, адаптивность и статический режим.
- `src/main.js` — запуск подсистем, ошибки подготовки и завершение.
- `src/scene/scene.js` — WebGL-сцена, портал, панорама, камера, качество и освобождение ресурсов.
- `src/scene/particles.js` — три плана песка и их обновление в общем цикле кадров.
- `src/scene/shaders.js` — GLSL песка и ограниченного светового перехода.
- `src/experience/flight.js` — чистая детерминированная модель состояния пролёта.
- `src/experience/scroll.js` — Lenis, ScrollTrigger, навигация и появление материала.
- `src/experience/interface.js` — активная глава, наклон и доступные пользовательские элементы.
- `public/assets/` — локальные фото, прозрачный портал, текстуры, шрифты и сведения об иллюстрациях.
- `tests/flight.test.js` — содержательные проверки модели пролёта.
- `tests/experience.browser.js` — воспроизводимые браузерные проверки, если доступен разрешённый автоматизированный браузер.
- `package.json`, `package-lock.json`, `.gitignore`, `README.md` — команды запуска и передачи проекта.
- `.impeccable/build/regions.json`, `.impeccable/build/spec.json` — измерения согласованного макета.

Каталоги проекта уже содержат пользовательские материалы. Не создавать второй checkout и не заменять содержимое папки стартовым шаблоном. Репозитория Git пока нет: коммиты выполняются только при наличии доступного репозитория; это не причина останавливать локальную поставку.

## Task 3: WebGL-пролёт, свет и песок

**Files:** `src/main.js`, `src/scene/scene.js`, `src/scene/particles.js`, `src/scene/shaders.js`, `src/experience/flight.js`, `src/experience/scroll.js`, `src/experience/interface.js`, `tests/flight.test.js`.

**Interfaces:**
- `sampleFlight(progress: number, reducedMotion: boolean): FlightState`, где `FlightState = { progress, cameraZ, portalOpacity, copyOpacity, flare, backgroundBlur, sandOpacity }`. `progress` ограничивается 0–1; все числа конечны; функция не зависит от предыдущего кадра.
- `createScene({ canvas, assets, reducedMotion, onFallback }): Promise<SceneApi>`; `assets = { gateway, giza, stone }`; `onFallback(reason: string): void`.
- `SceneApi = { setFlight(state), resize(width, height, pixelRatio), render(time, delta), setPaused(paused), dispose() }`.
- `createParticles({ scene, count, reducedMotion }): { update(time, delta, opacity), dispose() }`.
- `mountExperience({ sceneApi, reducedMotion }): () => void` — подключает прогресс и возвращает освобождение обработчиков.
- `mountInterface({ reducedMotion }): () => void` — подключает активную главу и наклон, возвращает очистку.

- [x] **Step 1:** Написать `tests/flight.test.js` для неверных и пограничных входов. Утверждения: `sampleFlight(-1,false).progress === 0`; `sampleFlight(2,false).progress === 1`; входы `NaN` и `Infinity` не порождают нечисловые поля; повторный вызов с тем же прогрессом после последовательности вперёд/назад возвращает тот же объект значений; при `reducedMotion` значения `flare` и `sandOpacity` равны 0. Выполнить `node --test tests/flight.test.js`; ожидается ошибка отсутствующего модуля.
- [x] **Step 2:** Реализовать `sampleFlight` с одной непрерывной кривой камеры и ограниченной засветкой у порога. Старт соответствует согласованному кадру, финал — выходу опор за поле зрения. Выполнить тот же тест; ожидается PASS.
- [x] **Step 3:** Реализовать `createScene`: реальная перспективная камера, объём опор и перемычки, детальные фотоматериалы, дальний фон, ограниченная GLSL-постобработка. При ошибке подготовки вызвать `onFallback`, не скрывать документ. Визуальная проверка: портал и горизонт действительно изменяются с разной глубиной.
- [x] **Step 4:** Реализовать три плана частиц с плавными потоками и небольшим световым акцентом. Обновлять сцену и частицы одним циклом, ограничить pixel ratio и число частиц по качеству; при скрытой вкладке вызвать `setPaused(true)`.
- [x] **Step 5:** Реализовать `mountExperience` и `mountInterface`. На компьютере синхронизировать Lenis и GSAP, пройти портал примерно за 2–3 высоты окна; на телефоне оставить нативную прокрутку. В уменьшенном движении не создавать длинное закрепление и непрерывную анимацию. При обычном указателе предел наклона таблички — 3°; при сенсорном вводе наклон отключён.
- [x] **Step 6:** В браузере быстро прокрутить вперёд и сразу назад, перейти через индекс к каждой главе и вернуться ко входу. Проверка: камера возвращается к текущему прогрессу без хвостов старой анимации; ссылки и кнопка ведут по одному маршруту; этап `motion` проходит.
